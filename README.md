# LLM Widget — скриншот → `claude-sonnet-5`

Ловит картинку из буфера обмена (Win+Shift+S), отправляет в **vibecode.moe** и показывает
ответ в прозрачном перетаскиваемом окне поверх всех окон. Токен, модель, system prompt
и прозрачность правятся в самом приложении, без перезапуска.

## Важно про эндпоинт

У vibecode.moe `claude-*` модели живут **не на `/v1/chat/completions`**, а на
`/v1/messages` в формате Anthropic. Проверено живым запросом:

```
POST /v1/chat/completions  → 400 "this model is only available via /v1/messages (Anthropic format)"
POST /v1/messages          → 200 OK
POST /v1/messages + image  → 200 OK   (vision работает)
```

Поэтому клиент умеет оба формата, и настройка **«Формат API»** по умолчанию стоит в `auto`:

| Модель | Эндпоинт | Формат картинки |
|---|---|---|
| `claude-*` | `POST /v1/messages` | блок `{"type":"image","source":{"type":"base64",...}}` |
| `gpt-*`, `gemini-*`, `grok-*`, … | `POST /v1/chat/completions` | блок `{"type":"image_url","image_url":{"url":"data:image/png;base64,..."}}` |

Авторизация в обоих случаях — `Authorization: Bearer vk-...`. В режиме `auto` формат
выбирается по имени модели, а если провайдер всё же ответит «эта модель на другом
эндпоинте», запрос автоматически повторяется во втором формате. Для `/v1/messages`
поле `max_tokens` обязательно — оно вынесено в настройки (по умолчанию 1024).

## Установка и запуск

```bash
pip install -r requirements.txt
```

```bash
python main.py
```

При первом запуске рядом с `main.py` появится `config.json` и откроется окно настроек:
вставьте ключ `vk-...`, нажмите «Проверить соединение», затем «Сохранить».

`config.json` в репозитории — шаблон с пустым токеном. После ввода ключа файл будет
содержать ваш `vk-...`, так что не коммитьте его изменения (`git update-index
--skip-worktree llm_widget/config.json` или держите конфиг рядом с .exe).

Дальше: делаете скриншот `Win+Shift+S` → через 2–5 секунд в виджете ответ модели.

## Горячие клавиши

| Клавиши | Действие |
|---|---|
| `Ctrl+Shift+H` | скрыть / показать виджет |
| `Ctrl+Shift+S` | открыть настройки |
| `Ctrl+Shift+P` | пауза / возобновление слежения за буфером |
| `Ctrl+Shift+Q` | выход |
| `Ctrl+Shift+X` | свернуть в трей (настраивается в ⚙) |
| `Ctrl+Alt+↑` / `Ctrl+Alt+↓` | прозрачность ±5 % |
| `Esc` (в фокусе виджета) | свернуть в трей |

Комбинацию сворачивания можно сменить в настройках: щёлкните поле **«Свернуть в трей»**
и нажмите нужные клавиши — например `Ctrl+Alt+M`. Нужен хотя бы один модификатор
(`Ctrl` / `Alt` / `Shift` / `Win`), иначе хоткей перехватывал бы обычный ввод во всей
системе. `Backspace`, `Delete` или кнопка «Очистить» отключают хоткей (сворачивание
останется на `Esc`, ✕ и трее). Новая комбинация начинает работать сразу после
«Сохранить», без перезапуска; текущая видна в подсказке кнопки ✕.

Если комбинацию уже занял кто-то другой, в тултипе трея появится «Хоткей … занят
другой программой» — выберите другую. Остальные хоткеи правятся в разделе `hotkeys`
файла `config.json` (имена клавиш — как их понимает пакет `keyboard`: `ctrl+shift+h`,
`ctrl+alt+up`).

Глобальные хоткеи держит пакет `keyboard`. Если он не установлен или система не даёт
поставить хук, приложение работает дальше — в тултипе трея появится пометка, что
хоткеи не активны; все действия останутся доступны через трей и кнопки виджета.

## Виджет

Тянется мышью за любую область, размер меняется за уголок справа снизу.
Кнопки: **⚙** настройки, **📋** копировать ответ, **✕** свернуть в трей.
Позиция, размер и прозрачность сохраняются в `config.json`.

Перетаскивание работает и по области текста, поэтому выделение мышью там отключено —
ответ копируется кнопкой 📋.

### Уточнения по скриншоту

Внизу виджета есть строка ввода. После первого ответа можно дописать вопрос и нажать
**Enter** (или **➤**) — скриншот и предыдущие ответы уходят вместе с вопросом, так что
модель отвечает в контексте той же картинки. Диалог копится в виджете, реплики
разделены линией, ваши вопросы помечены **Вы:**.

Пока запрос в полёте строка ввода заблокирована. Новый скриншот в буфере начинает
диалог с нуля. 📋 копирует всю переписку целиком.

## Настройки

| Поле | По умолчанию |
|---|---|
| API-токен (скрыт, 👁 показывает) | пусто |
| Base URL | `https://vibecode.moe/v1` |
| Модель (выпадашка, список тянется с сервера) | `claude-sonnet-5` |
| Формат API | `auto` (claude → `/messages`) |
| `max_tokens` | 1024 |
| System prompt | «Опиши, что на скриншоте. Отвечай кратко на русском.» |
| Прозрачность | 85 % |
| Свернуть в трей (захват комбинации) | `Ctrl+Shift+X` |
| Всегда поверх окон | вкл |
| Следить за буфером | вкл |

«Проверить соединение» шлёт короткий текстовый запрос текущими значениями полей
(ещё до сохранения), показывает результат под формой и заодно подтягивает актуальный
список моделей с `GET /v1/models` в выпадашку.

## Ошибки

Всё показывается текстом в виджете, приложение не падает:

- `401/403` → «Неверный токен»
- `402/429` → «Лимит / нет средств»
- `404` → «Модель или эндпоинт не найдены»
- `400` → текст причины от провайдера (например, про не тот эндпоинт)
- таймаут / нет сети → «Нет соединения»

Если ответ обрезался по `max_tokens`, в конце появляется пометка об этом.

Подробности пишутся в `app.log` рядом с приложением (ротация, 3 файла по 500 КБ).

## Сборка .exe

```bash
pyinstaller --noconsole --onefile --name LLMWidget main.py
```

Готовый файл — `dist/LLMWidget.exe`. `config.json` и `app.log` создаются рядом с .exe,
внутрь сборки их класть не нужно. Сборка тянет только PyQt6 + requests; `openai` нужен,
лишь если включить `use_sdk=True` в `llm_client.py`.

## Примеры system_prompt

Описание скриншота:

```
Опиши, что на скриншоте. Отвечай кратко на русском.
```

Перевод текста с картинки:

```
Найди на изображении весь текст и переведи его на русский.
Выведи только перевод, сохраняя структуру и переносы строк. Ничего не комментируй.
```

Решение задачи с картинки:

```
На изображении учебная задача. Реши её.
Дай краткий ход решения по шагам и выдели итоговый ответ жирным.
Формулы пиши в виде обычного текста.
```

Разбор ошибки / стектрейса:

```
На скриншоте сообщение об ошибке или стектрейс.
Назови вероятную причину и дай конкретные шаги для исправления.
Код показывай блоками с указанием языка. Отвечай по-русски, без вступлений.
```

Проверка вёрстки и UI:

```
Ты ревьюер интерфейсов. На скриншоте фрагмент UI.
Найди проблемы вёрстки, контраста и доступности, отсортируй по важности.
Максимум 5 пунктов, по одной строке на пункт, на русском.
```

## Проверка

```bash
python smoke_test.py
```

129 проверок без обращения к сети (HTTP замокан): выбор формата по модели, тела запросов
для `/messages` и `/chat/completions`, автоповтор в другом формате, коды ошибок API,
конфиг, прозрачность и хоткеи, markdown-рендер, drag/resize-геометрия, окно настроек,
перехват картинки из буфера с игнором текста и дублей, трей, многоходовой диалог
(уточнение уезжает вместе с картинкой и прошлым ответом в обоих форматах, строка ввода
блокируется на время запроса и чистится новым скриншотом) и захват комбинации клавиш
(модификаторы обязательны, стрелки переводятся в имена `keyboard`, очистка отключает
хоткей, старые конфиги без `hide_to_tray` получают значение по умолчанию).

Дополнительно проверено живыми запросами с реальным токеном: `claude-sonnet-5` со
скриншотом стектрейса, многоходовой диалог (картинка с числами → сумма → «перемножь те
же числа», ответ верный, то есть скриншот действительно уезжает с уточнением),
`claude-haiku-4-5`, `gpt-6-sol` и `gemini-3.6-flash` через openai-формат, сборка `.exe`
и её автономный запуск. Хоткей сворачивания проверен на живом `keyboard`: смена
комбинации через настройки перевешивает хук без перезапуска, старая комбинация
снимается, пустая отключает, прочие хоткеи переживают перерегистрацию.

## Модули

| Файл | За что отвечает |
|---|---|
| `main.py` | сборка приложения, трей, хоткеи, фоновый запрос |
| `config.py` | чтение/запись `config.json` |
| `llm_client.py` | два формата API (Anthropic `/messages` и OpenAI `/chat/completions`), разбор ответа и ошибок |
| `widget.py` | прозрачное окно: drag, resize, markdown, кнопки |
| `settings_dialog.py` | окно настроек, проверка соединения |
| `clipboard_watcher.py` | слежение за буфером, debounce 500 мс, дедуп по хешу |
| `tray.py` | иконка и меню в трее, статус в тултипе |
